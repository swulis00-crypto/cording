# 데이터 정확성 및 검수 원칙

KDC 탐험대는 학생에게 분류 지식을 가르치는 게임이므로, 화면보다 **데이터의 정확성**이 우선이다.

## 1. 기준 판본

- 모든 분류 데이터는 **KDC 제6판**을 기준으로 한다.
- 각 분류 항목의 `sourceEdition` 필드에 `"KDC 제6판"`을 기록한다.
- 판본을 바꾸면 모든 항목을 다시 대조하고 `reviewStatus`를 `needs-review`로 되돌린다.

## 2. 데이터를 만들 때 지키는 규칙

- 공식 분류명과 번호는 KDC 제6판 분류표와 대조한 값만 입력한다.
- 확인하지 못한 세부 구분의 명칭이나 번호는 **추정해서 만들지 않는다.**
- 공식 분류명(`name`)과 학생용 쉬운 설명(`learnerDescription`)은 별도 필드로 관리한다.
- 분류번호는 문자열로 저장한다. (`"000"`, 숫자 `0`이 아님)
- 실제 출판 도서를 예시로 쓸 때는 도서관 목록이나 신뢰할 수 있는 서지 정보로 분류번호를 확인한다.
- 직접 만든 예시 도서에는 **'가상 예시'**라고 표시한다.

## 3. 검수 상태

| 값 | 의미 | 게임 노출 |
|---|---|---|
| `draft` | 작성 중인 초안 | 미리보기 모드에서만 |
| `needs-review` | 작성 완료, 검토 대기 | 미리보기 모드에서만 (분류 데이터는 "검토 중" 표시와 함께 노출) |
| `approved` | 담당자 검토 완료 | 기본 플레이에 노출 |

- `approved`로 바꿀 수 있는 사람은 사서교사 또는 지정된 담당자다.
- 개발자(Claude Code 포함)는 초안을 `draft`나 `needs-review`로만 작성하고, 스스로 `approved`로 바꾸지 않는다.

## 4. 검수 절차 (PRD 16장)

1. KDC 제6판 분류표와 공식 분류명·번호를 대조한다.
2. 중학생용 쉬운 설명과 대표 주제를 검토한다.
3. 문항의 정답, 오답 해설, 표현, 난이도를 검토한다.
4. 이상이 없으면 `reviewStatus`를 `approved`로 바꾼다.
5. 학생 사용 후 혼동이 많은 문항을 보완하고 다시 검토한다.
6. 변경 시 판본, 날짜, 검토 상태를 기록한다.

## 5. 자동 검증 (PRD 9.5)

`npm run validate:data`와 테스트에서 다음을 검사한다.

- 분류 ID 중복 없음
- 분류번호와 분류명 필수
- 퀴즈 정답이 보기 중 하나와 일치
- 모든 퀴즈가 존재하는 분류 ID를 참조
- `approved` 문항은 문제·보기·정답·해설을 모두 가짐

## 6. 강목(100구분) 데이터

- 게임 2단계 구분표를 위해 classifications.json에 강목(level 2, `parentId`로 주류에 연결)을 넣었다. 모두 `needs-review`이다.
- 명칭을 확인하지 못한 번호는 데이터에 넣지 않고 화면에 "확인 필요"로 표시한다: **260, 610**
- 판본에 따라 달라질 수 있어 특히 확인이 필요한 번호: **960 오세아니아, 970 양극지방**, 310 통계자료, 530 공학 계열 명칭
- 확인한 명칭을 넣을 때는 다른 강목과 같은 형식으로 추가한다: `{ "id": "kdc-610", "code": "610", "name": "…", "parentId": "kdc-600", "level": 2, "sourceEdition": "KDC 제6판", "reviewStatus": "needs-review" }`
