# KDC 탐험대 개발 계획

- 기준 문서: [PRD_KDC_탐험대.md](../PRD_KDC_탐험대.md)
- 분류 기준 판본: **KDC 제6판**
- 게임 범위: 게임 1~4단계 (주류 → 분류기호 규칙 → 저자기호 → 청구기호). 상세는 [GAME_LEVELS.md](GAME_LEVELS.md)
- 진행 방식: 개발 단계마다 담당 선생님 검토를 받은 뒤 다음 단계로 넘어간다.
- 배포: https://swulis00-crypto.github.io/cording/ (main 푸시 시 GitHub Actions로 자동 배포)

> 이 문서의 "개발 단계"는 만드는 순서이고, "게임 단계"는 학생이 플레이하는 단계다.

## 1. 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 분류 판본 | KDC 제6판. 모든 분류 데이터의 `sourceEdition`은 `"KDC 제6판"` |
| 검토 전 문항 | 기본 플레이에서는 `approved` 문항만 출제. 개발·검수용 **미리보기 모드**(`?preview=1`)에서만 `draft` 문항을 "검토 전" 표시와 함께 노출 |
| 문항 수 | 주류당 3문항, 총 30문항 (유형: 명칭 기억 / 번호-명칭 연결 / 주제 분류 / 유사 영역 구별을 주류별로 나눠 배치) |
| 최종 복습 미션 | 주류 10개 완료 시 열림. 주류별 문항에서 무작위 출제 |
| 열쇠 지급 | 미션의 모든 문항에 답하면 정답률과 무관하게 지급. 별은 정답 수에 비례 |
| 화면 이동 | `HashRouter` (정적 호스팅·파일 실행에서도 새로고침·뒤로 가기 동작) |
| 오프라인 실행 | 일반 빌드와 함께 HTML 한 파일짜리 빌드(`vite-plugin-singlefile`)를 제공 |
| 효과음 | 음원 파일 대신 Web Audio API로 생성. 기본값 꺼짐 |
| 저장 | `localStorage`, 저장 형식에 `version` 필드. 손상 시 기본값으로 복구하고 안내 |
| 문항 형식 | 한 문항에 한 가지만 묻는다. 도서관 손님의 부탁·가상 예시 책 카드·잘못 꽂힌 책 찾기 등 상황형 |
| 분류 세부 원칙 | KDC 제6판 원칙 (예: 2000년 이후 한국 소설 813.7) |
| 주류 색상 | 한국십진분류표 라벨 색상. 밝은 색은 글자용 진한 색(`--cN-ink`)을 따로 둔다 |
| 게임 단계 열림 | 이전 단계를 마치면 다음 단계가 열림. 미리보기 모드에서는 모두 열림 |

## 2. 기술 스택

- React + TypeScript + Vite
- 스타일: CSS Modules + CSS 변수
- 테스트: Vitest + React Testing Library
- 데이터: `src/data/*.json` (분류, 퀴즈, 배지 조건)

```text
cording/
```

## 4. 단계별 작업

각 단계가 끝나면 git 커밋을 만들고 **변경 파일, 실행 명령, 실제 테스트 결과, 남은 문제**를 보고한다.

### 단계 0. 프로젝트 준비
- git 저장소 생성, Vite React-TS 프로젝트 생성, Vitest 설정
- 이 문서와 `DATA_POLICY.md` 작성
- 완료 조건: `npm run dev`, `npm test`, `npm run build`가 실제로 실행된다.

### 단계 1. 데이터 모델과 기본 화면 (FR-01, 02, 08, 09)
- 타입 정의(PRD 9.2~9.4), 주류 10개 데이터 입력(`needs-review`)
- 데이터 검증 함수(PRD 9.5)와 `validate:data` 스크립트
- 시작(SCR-01), 튜토리얼(SCR-02), 탐험 지도(SCR-03), 주류 소개(SCR-04), 도감(SCR-08)
- 768px 이상에서 가로 스크롤 없음, 키보드 포커스 표시
- 테스트: 10개 주류 번호순 표시, 잘못된 데이터 탐지

### 단계 2. 퀴즈 엔진 (FR-03~06)
- 미션 생성, 보기 섞기, 정답 판정, 점수 계산(정답 10점 / 오답 0점 / 힌트 감점 없음)
- 미션(SCR-05), 피드백(SCR-06), 결과(SCR-07)
- 퀴즈 초안 30문항(`draft`)
- 테스트: 판정, 정답률 계산(0문항 포함), 마지막 문항 후 결과 화면 이동, 미선택 제출 안내

### 단계 3. 진행 저장과 복습 (FR-07, FR-10)
- 저장소 모듈(읽기·쓰기·검증·버전 이전·초기화), 시도 기록 누적(최근 N개)
- 오답 복습(SCR-09), 설정(SCR-10), 초기화 확인 대화상자
- 게임 단계 선택 화면과 단계 열림 처리 (게임 2~4단계는 "준비 중" 표시)
- 테스트: 저장·복원, 손상 데이터, 초기화, 복습 목록 추가·제거, 단계 열림

### 단계 4. 게임 2단계 — 번호 속 비밀 풀기
- 인기 구역 강목 데이터(`level: 2`, `parentId`로 주류 연결, `needs-review`)
- 규칙 발견 화면, 번호 조립·규칙 추리 문항
- 테스트: 강목 데이터 검증, 번호 조립 판정

### 단계 5. 게임 3단계 — 저자기호 만들기
- 저자기호 계산 순수 함수(한글 자모 분해 + 제5표), 기호표 데이터
- 저자기호 공방(단계별 입력), 줄 세우기 발견, 실수 찾기, 거꾸로 추리
- 테스트: 제5표 전 항목, ㅊ 예외, 겹자음(ㄲ 등), 계산 예시(최67ㅂ 등)

### 단계 6. 게임 4단계 — 책 주소 완성하기
- 라벨 해부, 라벨 조립, 서가 정리(청구기호 정렬 함수: 저자기호 숫자는 소수로 비교)
- 실제 도서관 미션은 선택 (선생님 등록 데이터가 있을 때)
- 테스트: 청구기호 파싱·정렬

### 단계 7. 모험 요소 (FR-11, FR-12)
- 열쇠·별·배지(조건은 `badges.json`), 최종 복습 미션, 효과음, `prefers-reduced-motion` 대응
- 테스트: 배지 경계값, 중복 지급 없음, 효과음 끈 상태로 전체 흐름 완주

### 단계 8. 검증과 배포 마무리
- 전체 흐름 통합 테스트, 데이터 검증, 단일 파일 빌드 오프라인 확인
- README: 설치·실행·빌드·교사용 데이터 수정 방법
- PRD 18장 인수 기준 점검

## 5. 담당 선생님 작업

1. 단계 1 이후: 주류별 쉬운 설명·대표 주제 초안 검토
2. 단계 2 이후: 퀴즈 30문항 검토 후 `approved`로 변경
3. 단계 5 전: 저자기호 예시 책의 실제 분류기호(813.7 등)를 학교도서관 목록으로 확인
4. 단계 4~6 이후: 강목·저자기호·청구기호 문항 검토
5. 단계 8 이후: 학생 3~5명 사용성 테스트(PRD 13.2)

## 6. 범위에서 제외

100구분 전체(인기 구역만 다룸), 교사용 통계, 로그인, 순위표 (PRD 15장).
실제 도서관 책 찾기는 선생님이 검증된 책 목록을 등록할 때만 선택 기능으로 제공한다.
